# Méthodes Agile et démarche DevOps

Ce document couvre la partie **1.1.1 Méthodes Agile** et renforce le lien avec la partie **1.1.2 DevOps**.

---

## 1) Cadre Agile retenu

Le projet Hublot applique un cadre **Agile pragmatique** :

- **Backlog orienté valeur métier** : priorisation par risque RH (fiabilité des données, sécurité d'accès, lisibilité des tableaux).
- **User stories courtes** : chaque évolution est formulée en besoin utilisateur.
- **Critères d'acceptation** : exprimés dans les scénarios de test ST-F* / ST-SEC*.
- **Definition of Done** : CI verte + statuts de test à jour avant livraison.

---

## 2) Artefacts Agile réellement en place

| Artefact | Où | Rôle |
|----------|----|------|
| User stories / demandes | `SCENARIOS_TEST.md` + issues GitHub | Formaliser le besoin et la validation |
| Critères d'acceptation | `SCENARIOS_TEST.md` (Étant donné / Quand / Alors) | Rendre les attentes testables |
| Definition of Done | `PLANIFIER_EFFICACEMENT_LES_TESTS.md` + `VALIDER_RESULTATS_TESTS.md` | Décider si on peut livrer |
| Boucle de feedback rapide | `.github/workflows/ci.yml` | Détecter les régressions à chaque push |
| Revue et amélioration continue | `RAPPORT_EXECUTION_TESTS.md`, docs de synthèse | Capitaliser après campagne |

---

## 3) Pont Agile → DevOps

```mermaid
flowchart LR
  A[Besoin métier / User story] --> B[Critères d'acceptation]
  B --> C[Implémentation]
  C --> D[CI: lint+tests+audit+build+e2e]
  D --> E[Validation des résultats]
  E --> F[CD Netlify/NAS]
  F --> G[Monitoring & retours]
  G --> A
```

Ce flux garantit que la livraison continue reste alignée avec la valeur métier et la qualité attendue.

---

## 4) Check-list opérationnelle (avant merge)

- [ ] Besoin reformulé en user story claire
- [ ] Critères d'acceptation ajoutés ou mis à jour dans les scénarios ST-*
- [ ] CI verte sur la branche
- [ ] Statuts mis à jour dans `PLAN_TEST.md`
- [ ] Rapport ou preuve d'exécution disponible
