# 1.1.3.1 Guide Docker

## En bref

Docker permet de lancer Hublot dans un **environnement reproductible** : développement avec rechargement à chaud, **preview de production** sur le port 8080, ou **test local** sur le port 4173. Le projet utilise un **Dockerfile multi-stage** (build Node, service Nginx) et plusieurs fichiers `docker-compose` selon l'usage.

---

## Objectif pédagogique

Comprendre les **bases d'un environnement de test et de déploiement conteneurisé** : images, services, volumes, et reproduction du build de production en local.

---

## Contexte — projet Hublot

Hublot est une application **Vite + React** servie en production comme **fichiers statiques** (dossier `build/`). Docker ne remplace pas Netlify en production Studi, mais il sert à :

- Aligner le poste développeur sur la **cible Nginx** du NAS ;
- Exécuter la conversion Excel → JSON dans un conteneur Python isolé ;
- Valider le build avant un `rsync` vers le Synology.

---

## Définitions

| Terme | Définition |
|-------|------------|
| **Image** | Modèle immuable (OS + dépendances + application buildée). |
| **Conteneur** | Instance en cours d'exécution d'une image. |
| **Docker Compose** | Fichier YAML décrivant un ou plusieurs services (ports, volumes, build). |
| **Multi-stage** | Plusieurs étapes de build dans un Dockerfile ; seule la dernière étape utile est conservée (image légère). |
| **Volume** | Montage d'un dossier hôte dans le conteneur (code source, données). |

---

## Ce qui a été mis en place

| Fichier | Rôle |
|---------|------|
| `Dockerfile` | Stages `builder`, `production` (Nginx), `development` (Vite) |
| `docker-compose.dev.yml` | Service dev — http://localhost:3000 |
| `docker-compose.prod.yml` | Service prod — http://localhost:8080 |
| `docker-compose.test.yml` | Preview test — http://localhost:4173 |
| `docker-compose.yml` | Déploiement NAS (montage `build/`) |
| Scripts npm | `docker:dev`, `docker:prod`, `docker:prod:build`, `test:preview:docker` |

---

## Pourquoi Docker sur ce projet

| Choix | Justification |
|-------|----------------|
| Nginx en production | Même comportement que le NAS et la preview locale (fichiers statiques, SPA). |
| Service `converter` | Python + pandas sans polluer le poste macOS/Linux de chaque développeur. |
| Séparation dev / prod | Évite de confondre mode hot-reload et build optimisé. |

---

## Comment ça fonctionne

### Développement (hot-reload)

```bash
npm run docker:dev
# ou
docker compose -f docker-compose.dev.yml up
```

Application : **http://localhost:3000**

### Production locale (Nginx)

```bash
npm run docker:prod:build
# ou
docker compose -f docker-compose.prod.yml up --build -d
```

Application : **http://localhost:8080**

Les variables `VITE_APP_*` sont injectées **au build** : modifier `.env` puis **reconstruire** l'image.

### Test local (aligné CI / E2E)

```bash
npm run test:preview:docker
```

Lance un build de test et sert sur **http://localhost:4173** (identifiants dans `.env.test`).

### Conversion de données (conteneur Python)

```bash
npm run docker:convert
# ou, script principal actuel :
bash scripts/run-evolution-pipeline.sh --file "trdata/Suivi_des_emplois_en_ETPT_RPROG (23).xlsx"
```

---

## Quand

| Situation | Commande Docker |
|-----------|-----------------|
| Premier setup poste | `docker:dev` pour vérifier l'environnement |
| Avant démo « comme la prod » | `docker:prod:build` |
| Avant campagne E2E locale | `test:preview:docker` |
| Mise à jour `agents.json` | `run-evolution-pipeline.sh` (avec ou sans Docker selon poste) |
| Déploiement NAS | `docker-compose.yml` sur le Synology (voir 1.3.2) |

---

## Preuves et démonstration

```bash
docker compose -f docker-compose.dev.yml ps
docker compose -f docker-compose.prod.yml logs -f
npm run docker:stop
```

---

## Synthèse

> « Docker sur Hublot reproduit **dev**, **prod Nginx** et **preview test** via des compose dédiés. C'est l'outil qui rapproche le poste développeur du **NAS** et qui isole la **conversion Excel** sans imposer la même chaîne que Netlify en cloud. »
