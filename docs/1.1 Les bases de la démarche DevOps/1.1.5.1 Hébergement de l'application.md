# 1.1.5.1 Hébergement de l'application

## En bref

Hublot peut être hébergé de **trois manières** : **Netlify** (production Studi et démo), **Docker/Nginx** (VPS ou NAS), ou **build manuel + serveur web**. Le canal retenu pour la compétence est **Netlify** ; Docker et Nginx documentent l'option institutionnelle interne.

---

## Objectif pédagogique

Comprendre les **options d'hébergement** d'une application web statique et ce qui a été configuré pour Hublot en production.

---

## Contexte — projet Hublot

L'application est un **SPA React** : après `npm run build`, seul le dossier `build/` est servi. Les identifiants (`VITE_APP_USERNAME`, `VITE_APP_PASSWORD`) et l'URL des données (`VITE_APP_DATA_URL` ou `public/data/agents.json`) sont figés **au moment du build**.

---

## Définitions

| Terme | Définition |
|-------|------------|
| **Hébergement statique** | Serveur de fichiers HTML/JS/CSS sans logique serveur métier (hors fonctions optionnelles). |
| **CDN** | Réseau de diffusion (Netlify) pour servir les assets proche des utilisateurs. |
| **Publish directory** | Dossier déployé (`build/`). |
| **Variable `VITE_*`** | Variable injectée par Vite au build ; visible dans le bundle client. |

---

## Ce qui a été mis en place

### Production retenue — Netlify

| Élément | Valeur |
|---------|--------|
| URL | https://dirmhublot.netlify.app |
| Config | `netlify.toml` |
| Build | `npm run build` |
| Publish | `build/` |
| Données | `public/data/agents.json` dans le dépôt ou `VITE_APP_DATA_URL` |
| Secrets | Variables Netlify (jamais dans Git) |

### Alternatives documentées

| Méthode | Usage |
|---------|--------|
| `docker-compose.prod.yml` | VPS ou test local port 80/8080 |
| Build + Nginx | Serveur classique, `try_files` vers `index.html` |
| NAS Synology | `docker-compose.yml` + script 1.3.2 |

---

## Pourquoi Netlify en production Studi

| Avantage | Pour Hublot |
|----------|-------------|
| HTTPS automatique | Conformité sécurité sans gérer Certbot |
| Intégration Git | CD native + deploy previews |
| Headers | Définis dans `netlify.toml` |
| Gate CI | Required check sur workflow **CI** |

---

## Comment ça fonctionne (Netlify)

1. Créer un site Netlify connecté au dépôt `Meriem1403/Hublot`.
2. Netlify lit `netlify.toml` (commande, dossier, redirects SPA, headers).
3. Définir les variables d'environnement (identifiants, Sentry optionnel).
4. Activer **Deploy only when required checks pass** → check **CI**.
5. Chaque push sur `main` déclenche build + publish.

**Données en prod :** inclure `public/data/agents.json` (généré par `run-evolution-pipeline.sh`) ou pointer `VITE_APP_DATA_URL` vers une URL hébergée.

### Docker (rappel)

```bash
npm run docker:prod:build
# http://localhost:8080 — variables VITE_* dans .env avant build
```

---

## Quand

| Besoin | Hébergement |
|--------|-------------|
| Démonstration / production | Netlify prod |
| Préproduction | Branche `staging` / deploy preview |
| Réseau interne DIRM | NAS + Docker |
| Test iso prod local | Docker prod ou `npm run preview:test` |

---

## Preuves et démonstration

- Site live : https://dirmhublot.netlify.app
- Config : `netlify.toml` à la racine du dépôt
- Santé : `curl https://dirmhublot.netlify.app/health.json`
