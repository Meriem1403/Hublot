# 1.2.10 Guide Playwright

## En bref

**Playwright** pilote un navigateur réel pour les tests **E2E** de Hublot : login, tableau de bord, campagne ST-F*. En CI, les tests tournent **headless** ; en démo, `npm run test:e2e:demo` affiche le parcours en ralenti. Vitest couvre les **48 tests unitaires** sans navigateur. Fichiers : `playwright.config.ts`, dossier `e2e/`.

---

## Objectif pédagogique

Utiliser **Playwright** pour les tests end-to-end : installation, commandes, démonstration, CI, dépannage.

---

## Contexte — projet Hublot

Le parcours critique (connexion → dashboard → health) doit bloquer la livraison si régressé. Playwright rejoue ce parcours sur une preview locale (`build:e2e`, `127.0.0.1:4173`), identique au runner GitHub Actions du dépôt `Meriem1403/Hublot`.

---

## Définitions

| Terme | Définition |
|-------|------------|
| **E2E** | Test bout en bout dans un navigateur. |
| **Headless** | Sans fenêtre visible (CI). |
| **Headed** | Fenêtre visible (démo). |
| **slowMo** | Délai entre actions (`PLAYWRIGHT_SLOW_MS`). |
| **webServer** | Preview démarrée automatiquement par Playwright. |
| **Smoke** | 3 tests minimaux `e2e/smoke.spec.ts`. |

---

## Ce qui a été mis en place

| Commande | Fenêtre | Usage |
|----------|---------|--------|
| `npm run test:e2e` | Non (headless) | CI, vérif locale |
| `npm run test:e2e:demo` | Oui, ~800 ms | **Démonstration** |
| `npm run test:e2e:slow` | Oui, ~400 ms | Démo plus vive |
| `npm run test:e2e:headed` | Oui, rapide | Debug visuel |
| `npm run test:e2e:ui` | UI Playwright | Un test à la fois, replay |
| `npm run test:campaign` | Headless | ST-F01… + prod lecture seule |

Fichiers :

```
e2e/
  smoke.spec.ts              # 3 tests — parcours critique
  campaign-manual.spec.ts    # ST-F01…F06
  campaign-prod.spec.ts      # vérifs prod lecture seule
playwright.config.ts         # port 4173, webServer, slowMo
```

### Scénario `smoke.spec.ts`

| # | Test | Vérification |
|---|------|--------------|
| 1 | Page de connexion | « Bienvenue », champs, bouton Se connecter |
| 2 | Connexion → dashboard | `e2e-user` / `e2e-pass`, bouton Déconnexion |
| 3 | `health.json` | `{ "status": "ok", "app": "hublot" }` |

Identifiants **uniquement** pour `build:e2e`, pas les secrets Netlify prod.

---

## Pourquoi ces choix

Playwright complète Vitest : il valide l'intégration UI (AuthGuard, routing) que les unitaires ne voient pas. Peu de tests E2E (3 smoke) limitent la fragilité et la durée CI. Le ralenti 800 ms rend la démo lisible sans mode `--debug` (pause manuelle).

---

## Comment ça fonctionne

1. `npm run build:e2e` — build avec `e2e-user` / `e2e-pass`, badge QA.
2. Playwright démarre `preview` sur **http://127.0.0.1:4173**.
3. Exécution des `*.spec.ts`.
4. Arrêt du serveur (sauf mode UI).

Configuration : `playwright.config.ts` à la racine du dépôt.

### Déroulé de démonstration (3–5 min)

1. Intro : Vitest vs Playwright, headless vs headed.
2. `npm run test:e2e:demo` — commenter login et dashboard.
3. Montrer **3 passed** dans le terminal.
4. Lien CI : même commande dans `ci.yml`.
5. Optionnel : `npm run security:headers` sur prod (ST-SEC01).

### Mode interface

```bash
npm run test:e2e:ui
```

Ouvrir `smoke.spec.ts`, lancer un test, utiliser la timeline pour expliquer pas à pas.

### Ajuster le ralenti

| `PLAYWRIGHT_SLOW_MS` | Effet |
|----------------------|--------|
| 0 | Vitesse normale |
| 400 | `test:e2e:slow` |
| 800 | `test:e2e:demo` |
| 1200 | Très lent (vidéo) |

## Quand

| Moment | Commande |
|--------|----------|
| Chaque push / PR | `test:e2e` en CI |
| Avant livraison | `test:e2e:demo` une fois |
| Campagne plan test | `test:campaign` |
| Debug UI | `test:e2e:ui` |

## Preuves et démonstration

```bash
npm ci
npx playwright install chromium
npm run test:e2e:demo
# Attendu : 3 passed

npm run test:campaign
# Attendu : 9 passed (référence rapport 2026-05-27)
```

| | Local démo | GitHub Actions |
|---|------------|----------------|
| Fenêtre | Visible (`test:e2e:demo`) | Headless |
| URL | 127.0.0.1:4173 | Idem sur runner |
| Preuve | Terminal + `playwright-report/` | Job **E2E** vert |

### Pièges fréquents

| Problème | Solution |
|----------|----------|
| Trop rapide | `test:e2e:demo` ou `PLAYWRIGHT_SLOW_MS=1200` |
| `--debug` + page blanche | Cliquer Resume ; préférer demo ou UI |
| Premier lancement long | Attendre `build:e2e` (~20 s) |
| Port 4173 occupé | `lsof -i :4173`, fermer autre preview |
| Tester vraie prod login | Utiliser `campaign-prod.spec.ts` (lecture seule) |

### Checklist avant livraison

- [ ] `npm ci` + `playwright install chromium`
- [ ] `npm run test:e2e:demo` → 3 passed
- [ ] Expliquer Vitest vs Playwright
- [ ] Onglet Actions CI (job E2E) prêt

---

## Synthèse

Playwright verrouille le parcours utilisateur critique de Hublot en local et en CI ; la démonstration utilise `test:e2e:demo`, la campagne documentée `test:campaign` pour les scénarios ST-F*.
