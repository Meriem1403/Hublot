# 1.2.4.2 Sécurité du déploiement

## En bref

La sécurité du **déploiement** Hublot repose sur HTTPS Netlify, variables d'environnement hors Git, exclusion des données RH du dépôt, en-têtes HTTP durcis et audit npm bloquant en CI. L'authentification applicative protège l'accès au tableau de bord sur `https://dirmhublot.netlify.app`. Annexe associée : [Annexe 07](../Annexes/Annexe_07_SECURITE_4_DEPLOIEMENT.md).

---

## Objectif pédagogique

Mettre en œuvre la **sécurité du déploiement** : transport, secrets, exposition des fichiers, headers, audit des dépendances.

---

## Contexte — projet Hublot

Le site public est hébergé par Netlify (branche `main`). Un déploiement alternatif NAS utilise nginx (`nginx.conf`). Les secrets (mots de passe, URL Neon) ne doivent jamais apparaître dans le dépôt `Meriem1403/Hublot`.

---

## Définitions

| Terme | Définition |
|-------|------------|
| **TLS / HTTPS** | Chiffrement du transport — géré par Netlify en prod. |
| **Variable d'environnement** | Secret ou config injecté au build (ex. `VITE_APP_PASSWORD`). |
| **Header de sécurité** | Directive HTTP (X-Frame-Options, HSTS, etc.). |
| **audit:prod** | Audit npm limité aux dépendances de production. |

---

## Ce qui a été mis en place

### HTTPS

| Canal | Mise en œuvre |
|-------|----------------|
| **Netlify (PROD)** | Certificat TLS automatique |
| **NAS (local)** | HTTP par défaut ; HTTPS via reverse proxy DSM + certificat interne |

### Variables d'environnement et secrets

| Variable (exemples) | Où | Usage |
|---------------------|-----|--------|
| `VITE_APP_USERNAME` | Netlify | Connexion application |
| `VITE_APP_PASSWORD` | Netlify | Connexion application |
| `NETLIFY_DATABASE_URL` | Netlify (Neon) | Base PostgreSQL |

Local : fichier `.env` (`.gitignore`). Règles : pas de commit de secrets ; rotation en cas de fuite ; données RH hors dépôt public.

### Headers de sécurité (`netlify.toml`)

| Header | Valeur | Protection |
|--------|--------|------------|
| `X-Frame-Options` | `DENY` | Clickjacking |
| `X-Content-Type-Options` | `nosniff` | MIME sniffing |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | Fuite de référent |
| `Permissions-Policy` | camera/micro/geo désactivés | Permissions navigateur |

### Audit npm en CI

`npm run audit:prod` est **bloquant** dans `ci.yml` — politique en [1.2.4.3](./1.2.4.3%20Audit%20des%20d%C3%A9pendances.md).

### Authentification applicative

Page de connexion ; identifiants au build ; session navigateur — tests ST-F01, E2E Playwright.

---

## Pourquoi ces choix

Netlify fournit TLS et headers sans administrer un serveur. Séparer secrets et code évite les fuites dans l'historique Git. L'audit **production** évite de bloquer sur des CVE uniquement liées aux outils de dev (Vitest). Les headers compensent l'exposition d'une SPA statique sans backend d'auth dédié.

---

## Comment ça fonctionne

1. Push sur `main` → CI (lint, 48 tests, `audit:prod`, build, E2E).
2. Si CI verte → Netlify build `npm run build` et publie `build/`.
3. Netlify injecte les variables et applique les headers de `netlify.toml`.
4. Contrôle post-deploy : `npm run security:headers` (ST-SEC01).

```bash
curl -I https://dirmhublot.netlify.app
```

Attendu : URL en `https://`, réponse `200` ou `304`, en-têtes `x-frame-options`, `x-content-type-options`.

---

## Quand

| Moment | Action |
|--------|--------|
| Chaque push `main` / `staging` | CI + audit prod |
| Après chaque deploy prod | Vérification headers (ST-SEC01) |
| Avant mise en prod | [1.2.4.4 Checklist](./1.2.4.4%20Checklist%20s%C3%A9curit%C3%A9.md) |
| Incident suspect | Rotation mots de passe Netlify |

---

## Preuves et démonstration

```bash
curl -I https://dirmhublot.netlify.app
npm run audit:prod
npm run security:headers
```

| Preuve | Attendu |
|--------|---------|
| CI job Audit npm | Exit 0 |
| `security:headers` | Exit 0, X-Frame-Options + nosniff |
| `.gitignore` | `.env`, `agents.json`, `*.xlsx` exclus |

Checklist complète : [1.2.4.4](./1.2.4.4%20Checklist%20s%C3%A9curit%C3%A9.md). Mesures applicatives : [1.2.4.1](./1.2.4.1%20Mesures%20de%20s%C3%A9curit%C3%A9%20applicative.md).

## Synthèse

Le déploiement Hublot est sécurisé par HTTPS, secrets hors Git, headers HTTP, audit npm en CI et authentification avant accès aux tableaux de bord RH.
