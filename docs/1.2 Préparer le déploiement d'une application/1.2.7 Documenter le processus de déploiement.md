# 1.2.7 Documenter le processus de déploiement

## En bref

Ce chapitre documente comment **installer**, **déployer**, **rollback** et **observer** Hublot : procédure locale, configuration Netlify, architecture Git → CI → CD, captures du pipeline et consultation des logs. Le site de production est `https://dirmhublot.netlify.app` ; le dépôt source est `Meriem1403/Hublot`.

---

## Objectif pédagogique

**Documenter le processus de déploiement** d'une application : installation, rollback, architecture, pipeline CI et logs de build.

---

## Contexte — projet Hublot

L'équipe DIRM doit pouvoir reproduire un déploiement, revenir en arrière après incident et comprendre où lire les logs (GitHub Actions vs Netlify). La documentation s'appuie sur les annexes numérotées du dossier `docs/Annexes/`.

---

## Définitions

| Terme | Définition |
|-------|------------|
| **CI** | GitHub Actions — qualité avant merge. |
| **CD** | Netlify — build et publication après push `main`. |
| **Rollback** | Republier un deploy antérieur ou revert Git. |
| **Artefact** | Dossier `build/` publié par Netlify. |
| **Required checks** | Jobs CI obligatoires avant deploy. |

## Ce qui a été mis en place

### Procédure d'installation locale

Prérequis : Node.js 20 LTS, npm, accès GitHub et Netlify.

```bash
git clone https://github.com/Meriem1403/Hublot.git
cd Hublot
npm ci
# .env local (jamais commité) : VITE_APP_USERNAME, VITE_APP_PASSWORD
npm run dev
```

Application : `http://localhost:5173`.

Vérification avant déploiement :

```bash
npm run test:run    # 48 tests
npm run build       # génère build/
```

### Déploiement Netlify

1. *Add new site* → importer **Meriem1403/Hublot**, branche **main**.
2. Build command : `npm run build` ; publish directory : `build` (`netlify.toml`).
3. Variables : `VITE_APP_USERNAME`, `VITE_APP_PASSWORD`, `NETLIFY_DATABASE_URL` (Neon).
4. Chaque push `main` déclenche build + deploy → `https://dirmhublot.netlify.app`.

### Architecture

```
Développeur → git push main
  → GitHub (Meriem1403/Hublot)
  → GitHub Actions CI (lint, 48 tests, audit, build, E2E)
  → Netlify CD (npm run build → publish build/)
  → https://dirmhublot.netlify.app
```

## Pourquoi ces choix

Documenter le rollback **Netlify** (option A) permet un retour rapide sans revert Git. L'option B (revert Git) aligne le dépôt et la prod quand nécessaire. Séparer logs **Actions** (qualité) et logs **Netlify** (build publish) évite de chercher une erreur de test dans les logs Vite Netlify.

---

## Comment ça fonctionne

### Rollback option A (Netlify)

1. Netlify → **Deploys**.
2. Choisir un deploy *Published* antérieur stable.
3. **Publish deploy** / *Restore* — le code Git inchangé.

### Rollback option B (Git)

```bash
git log --oneline
git revert --no-commit abc1234..HEAD
git commit -m "Rollback: retour à la version stable"
git push origin main
```

Netlify redéploie le commit résultant.

**Recommandation :** option A pour urgence prod ; option B pour aligner historique.

### Pipeline CI — étapes à capturer

| Étape | Action |
|-------|--------|
| Checkout | Code du commit |
| Setup Node.js 20 | Cache npm |
| Install | `npm ci` |
| ESLint | `npm run lint` |
| Tests | `npm run test:run` (48) |
| Audit | `npm run audit:prod` |
| Build | `npm run build` |
| E2E | `npm run test:e2e` |

Capture : onglet [Actions](https://github.com/Meriem1403/Hublot/actions) → workflow **CI** → job vert.

### Logs de build

| Source | Accès | Contenu |
|--------|-------|---------|
| **GitHub Actions** | Dépôt → Actions → run → job | Tests, audit, erreurs compile |
| **Netlify** | Dashboard → Deploys → deploy | Sortie `npm run build`, publish |
