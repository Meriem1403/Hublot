# 1.2.8 Procédure d'exécution des tests
## En bref

Ce chapitre liste les **commandes et étapes** pour reproduire de manière reproductible les résultats du plan de test Hublot : 48 tests Vitest, build, CI GitHub, contrôles prod, démo Playwright. Annexe associée : [Annexe 09](../Annexes/Annexe_09_DEMO_EPREUVE.md).

---

## Objectif pédagogique

Exécuter et **démontrer** la procédure de tests dans le cadre de validation (reproductibilité, preuves).

---

## Contexte — projet Hublot

Le référentiel exige de prouver que les tests du plan sont rejouables sur un poste de travail standard et alignés avec la CI du dépôt `Meriem1403/Hublot` et le site `dirmhublot.netlify.app`.

---

## Définitions

| Terme | Définition |
|-------|------------|
| **Validation** | Vérification reproductible avec commandes documentées. |
| **QA local** | Preview `build:e2e` sur `127.0.0.1:4173`. |
| **Smoke E2E** | 3 tests Playwright `e2e/smoke.spec.ts`. |

---

## Ce qui a été mis en place

Ordre d'exécution documenté : unitaires → CI → E2E → headers prod → sécurité / rollback. Scripts npm : `test:run`, `build`, `test:e2e`, `test:e2e:demo`, `security:headers`, `test:campaign`.

---

## Pourquoi ces choix

L'ordre suit la pyramide (rapide d'abord) pour une exécution efficace. Les commandes locales reflètent la CI pour garantir la cohérence. La prod n'est testée qu'en lecture seule (headers, sans manipulation de secrets de connexion en production).

---

## Comment ça fonctionne

### Prérequis

```bash
cd /chemin/vers/Hublot   # clone Meriem1403/Hublot
node -v                  # v18+, CI utilise Node 20
npm ci
npx playwright install chromium   # une fois
```

### 1. Tests unitaires (obligatoire)

```bash
npm run test:run
```

**Attendu :** 48 tests passés, 0 échec. Capture : `Tests 48 passed` (Vitest).

### 2. Build de production

```bash
npm run build
ls -la build/index.html build/assets/
```

**Attendu :** dossier `build/` avec `index.html` et `assets/`.

### 3. Audit des dépendances

```bash
npm run audit:prod
```

**Attendu :** exit 0 (identique à la CI bloquante).

### 4. Application en local (DEV)

```bash
npm run dev
```

Ouvrir `http://localhost:5173` — connexion, onglets, filtres (checklist manuelle rapide).

### 5. Vérification CI (TEST)

1. [github.com/Meriem1403/Hublot/actions](https://github.com/Meriem1403/Hublot/actions)
2. Dernier run **CI** sur `main` — job vert
3. Phrase type : « Chaque push déclenche lint, 48 tests, audit, build, E2E. »

### 6. Production (PROD)

URL : `https://dirmhublot.netlify.app`

```bash
curl -I https://dirmhublot.netlify.app
# ou
npm run security:headers
```

Vérifier `x-frame-options`, `x-content-type-options`. Tests manuels : voir [1.3.7](../1.3%20R%C3%A9diger%20des%20scriptes%20dans%20la%20d%C3%A9marche%20DevOps/1.3.7%20Automatiser%20les%20tests%20en%20DevOps.md).

### 7. Démo Playwright

```bash
npm run test:e2e:demo
```

**Attendu :** 3 passed sur `e2e/smoke.spec.ts`. Guide : [1.2.10](./1.2.10%20Guide%20Playwright.md).

### 8. Rollback (optionnel)

Netlify → Deploys → **Publish deploy** antérieur. Détail : [1.2.7](./1.2.7%20Documenter%20le%20processus%20de%20d%C3%A9ploiement.md).

### 9. NAS (optionnel)

[1.3.2 Rédiger et utiliser un script de déploiement](../1.3%20R%C3%A9diger%20des%20scriptes%20dans%20la%20d%C3%A9marche%20DevOps/1.3.2%20R%C3%A9diger%20et%20utiliser%20un%20script%20de%20d%C3%A9ploiement.md).

## Preuves et démonstration

### Ordre d'exécution recommandé

| # | Action | Durée |
|---|--------|-------|
| 1 | `npm run test:run` | ~2 min |
| 2 | GitHub Actions CI vert | ~1 min |
| 3 | `npm run test:e2e:demo` ou prod lecture seule | ~3 min |
| 4 | `curl -I` ou `security:headers` | ~30 s |
| 5 | Rollback + [1.2.4.2](./1.2.4.2%20S%C3%A9curit%C3%A9%20du%20d%C3%A9ploiement.md) | ~1 min |

Validation des statuts : [1.2.6](./1.2.6%20Valider%20les%20r%C3%A9sultats%20des%20tests.md).
