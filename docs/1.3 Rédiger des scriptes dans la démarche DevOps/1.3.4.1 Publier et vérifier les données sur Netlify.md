# 1.3.4.1 Publier et vérifier les données sur Netlify

## En bref

Ce chapitre explique **comment publier** les données RH de Hublot sur **Netlify** et **vérifier** qu'elles s'affichent sur `https://dirmhublot.netlify.app`. Deux modes existent : JSON statique dans le dépôt (recommandé par défaut) ou base **Neon** via `NETLIFY_DATABASE_URL`. Dans les deux cas, la chaîne d'évolution (`run-evolution-pipeline.sh`, `convert_suivi_etpt_to_json.py`) précède la publication.

---

## Objectif pédagogique

**Publier et vérifier des données** dans un déploiement continu : artefact `public/data/agents.json`, commandes npm, variables d'environnement, contrôle post-déploiement.

---

## Contexte — projet Hublot

L'application React charge les effectifs via `/data/agents.json` (fichier statique) ou via l'API Neon si `NETLIFY_DATABASE_URL` est définie sur Netlify. Après un export Excel DIRM, les graphiques (région, service, ETP) ne se mettent à jour en production que si les données suivent le **git push** (option 1) ou un **push Neon** (option 2), puis le rebuild Netlify déclenché par la CD.

---

## Définitions

| Terme | Définition |
|-------|------------|
| **`public/data/agents.json`** | Fichier servi tel quel par Netlify (option 1). |
| **`copy-data-for-netlify`** | Script npm qui copie `src/data` → `public/data`. |
| **Neon** | PostgreSQL managé (extension Netlify DB). |
| **`push-agents-to-neon`** | Script Node qui insère les agents en base. |

---

## Ce qui a été mis en place

| Élément | Fichier / commande |
|---------|-------------------|
| Conversion | `convert_suivi_etpt_to_json.py` → `public/data/agents.json` |
| Orchestration | `run-evolution-pipeline.sh --file …` |
| Copie de secours | `npm run copy-data-for-netlify` (`scripts/copy-data-for-netlify.js`) |
| Push base | `npm run push-agents-to-neon` (`scripts/push-agents-to-neon.js`) |
| CD | Netlify build `npm run build`, publish `build/` |
| Qualité amont | `.github/workflows/ci.yml` — 48 tests avant merge |

---

## Pourquoi ces choix

**Option 1 (JSON commité)** : simple, auditable dans Git, pas de secret base obligatoire — adapté en audit et aux premières mises en prod. **Option 2 (Neon)** : utile si les données ne doivent pas transiter dans le dépôt ou pour évolutions fréquentes sans rebuild lourd ; nécessite `NETLIFY_DATABASE_URL` et discipline sur `push-agents-to-neon`. Nous recommandons de **toujours** passer par le pipeline d'évolution pour garantir IDs uniques et services renseignés avant toute publication.

---

## Comment ça fonctionne

### Étape 0 — Produire des données valides

```bash
bash scripts/run-evolution-pipeline.sh \
  --file "trdata/Suivi_des_emplois_en_ETPT_RPROG (23).xlsx"
```

Vérifier les compteurs affichés (agents totaux / actifs).

### Option 1 — Sans base de données (recommandée si Neon non configuré)

1. Les fichiers sont déjà dans `public/data/agents.json` après conversion (et `src/data/agents.json`).
2. Si vous n'avez modifié que `src/data` :

   ```bash
   npm run copy-data-for-netlify
   ```

3. Versionner et pousser :

   ```bash
   git add public/data/agents.json
   git commit -m "Données RH : export ETPT"
   git push origin main
   ```

4. Attendre le déploiement Netlify (1–2 min). Ouvrir `https://dirmhublot.netlify.app`, se connecter, contrôler les indicateurs et filtres région/service.

### Option 2 — Avec Neon (Netlify DB déjà connectée)

1. Copier `NETLIFY_DATABASE_URL` depuis **Netlify → Site settings → Environment variables** vers `.env` local (ne jamais committer `.env`).
2. Pousser les données :

   ```bash
   npm run push-agents-to-neon
   ```

   Ou via le pipeline :

   ```bash
   bash scripts/run-evolution-pipeline.sh --file "trdata/....xlsx" --push-neon
   ```

3. `git push` si le code applicatif a changé ; Netlify rebuilde et l'app lit la base via la variable d'environnement.

### Vérification post-déploiement

| Contrôle | Méthode |
|----------|---------|
| Fichier statique | `curl -s https://dirmhublot.netlify.app/data/agents.json \| head` |
| UI | Login → onglets Overview / missions — effectifs cohérents |
| Non-régression | Dernier run **CI** vert sur le commit déployé |
| Sécurité | Données RH : accès authentifié uniquement (pas d'exposition publique non voulue des PII en dehors du périmètre prévu) |

---

## Quand

| Événement | Action |
|-----------|--------|
| Nouvel export mensuel | Pipeline → option 1 ou 2 → vérif UI |
| Premier déploiement Netlify | Option 1 après premier `agents.json` |
| Extension Neon activée sur le site | Migrer vers option 2 |
| Échec affichage vide | Vérifier présence `public/data/agents.json` dans le commit déployé |

---

## Preuves et démonstration

```bash
# Local
bash scripts/run-evolution-pipeline.sh --file "trdata/Suivi_des_emplois_en_ETPT_RPROG (23).xlsx"
npm run test:run   # 48 passed

# Après push main — URL prod
curl -sI https://dirmhublot.netlify.app/data/agents.json | head -5
```

Capture attendue pour la traçabilité : dashboard Hublot avec graphiques alimentés, deploy Netlify *Published* sur le SHA du commit données, workflow **CI** vert sur le même SHA.

---

## Synthèse

Publier les données Hublot sur Netlify, c'est d'abord générer un `agents.json` validé par le pipeline d'évolution, puis le committer (option 1) ou le pousser vers Neon (option 2), et contrôler l'URL de production après CD.
